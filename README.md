# 同页对照 PDF 工具

把一份**英文 PDF** + 对应的**单语中文译文 PDF**，合成为"英文原文在上、蓝色中文紧跟其下"的**同页双语对照 PDF**——保留原图、表格、电路图的版式，不丢任何内容。

> **许可证**：本项目以 **AGPL-3.0** 发布。核心引擎依赖 PyMuPDF（AGPL-3.0 或商业双许可），
> 在线翻译路径依赖 pdf2zh_next / babeldoc（均为 AGPL-3.0）。闭源分发需自行购买
> PyMuPDF 商业许可。详见 [DEPENDENCIES.md](DEPENDENCIES.md)。
>
> **关于样张代号**：README 与代码中的 `DOC-A01`、`DOC-B01` 等为**脱敏代号**，
> 仓库中不含任何真实客户文档与其原始型号。

## 快速开始

### 方式一：双击 `同页对照工具.exe`（推荐，无需 Python / 无需本 README 之外的一切）

1. 双击 exe（可放桌面/任何文件夹，**单文件 30MB，自包含**）；
2. 选"英文原文 PDF"；"中文译文"留空即自动在同目录及 `translated\` 里找 mono 译文，找不到且勾选"自动在线翻译"则调 pdf2zh 翻译；
   整页竖排的图纸（PCB/机械图）会先自动**转正**再翻译合成（勾选"竖排图纸转正"可关掉）——否则 pdf2zh 根本看不见竖着的正文；
3. 输出路径自动填好（原文目录 `translated\<名> 同页对照.pdf`，可改）；
4. 点 **▶ 开始生成**，日志区实时滚动，底部状态条给出结果：
   `✔ 完成：撕裂 0 / 碰撞 0 / 排版 OK — 可交付`；勾了深检还会做像素级 0 丢失 + 覆盖率核查；
   若合成后质检仍报告警，**不会只警告了事**：自动进入修复循环（加大切带边距 → 把仍会压字的中文块改排到该页页末），逐级重试直到撕裂/碰撞清零，日志会写明"✔ 自动修复成功（第 N 轮）"；
   **排版可读性（质检⑤）单独把关**：撕裂/碰撞/像素只回答"原文有没有被弄坏、中文有没有压字"，对"整页译文被堆到页面另一头"完全失明（旧版把 572 个译文块里的 229 个丢到页末，三条质检照样全 0 报"可交付"）。质检⑤量的是"每个译文块落在离它自己的原文多远"和"有多少块被堆到页末"，超标即判不通过，不再冒充可交付；
5. 完成后直接点"打开成品"/"打开所在文件夹"。

也可把英文 PDF **拖到 exe 图标上**，路径自动填入。

`DualGuiCLI.exe` 是同一核心的命令行版（脚本/回归用）：

```powershell
.\DualGuiCLI.exe --cli 英文原文.pdf [-o 输出.pdf] [--mono 译文.pdf] [--deep] [--no-rotate]   # 退出码 0=全部通过
```

> 术语表外置：exe 同目录放 `heading_glossary.json` 即可被读取（优先级高于内嵌副本），改词表无需重新打包。
> 在线翻译依赖本机的 `pdf2zh_next.exe`（点"pdf2zh 路径…"指定）；没有翻译环境就把现成 mono 译文选好即可。

### 方式二：命令行（有 Python 时，与 exe 同一套脚本）

```powershell
$py = "python"   # 任意装有 pymupdf 的 Python（也可用 $env:DUAL_PY 指定）

# A：已有单语中文译文（pdf2zh 产出的 *.mono.pdf，会先在 translated\ 里自动找）
& $py make_dual.py 英文原文.pdf --mono 中文译文.pdf -o 同页对照.pdf

# B：先在线翻译成中文，再合成
& $py make_dual.py 英文原文.pdf --translate --engine siliconfree

# C：交付前深检（像素级 0 丢失 + 中文覆盖率，较慢）
& $py make_dual.py 英文原文.pdf --mono 中文译文.pdf -o 同页对照.pdf --deep-qa
```

也可以把英文 PDF **直接拖到** `拖我-生成同页对照.cmd` 上（旁边/`translated\` 里有 mono 译文即可）。

输出末尾打印 `撕裂=0 碰撞=0 排版告警=0` 即通过；`--deep-qa` 再打印 `未解释像素差页=0`。
合成器还会打印一行 `排版距离：N 个译文块中有 M 个落点距其原文 >120pt`，正常成品应在 1% 以内。

## 拷到另一台电脑（便携包）

把 `同页对照工具-便携包` 整个文件夹（或其 zip）拷到任意 Windows 10/11 机器，解压即用，
**目标机无需安装 Python / pdf2zh / VC++ 运行库**：

- 三个 exe 必须留在同一目录（启动器与 DualEngine 分离是刻意的，防打包器污染翻译子进程，见踩坑表）
- `engine\python\`：内置便携 Python 3.12 + pdf2zh_next（gradio/FastAPI 等无关大件已剔除）
- `engine\models\.cache\`：babeldoc 版面模型 + 字体已预置，首跑零下载
- `vcruntime140*.dll / msvcp140.dll` 已随 engine\python 放置

注意：①"在线翻译"仍需**联网**（免费翻译接口在云端）；若只用现成译文（拖 mono 或 `--mono`）则完全离线。②在线接口有免费额度限速，大文件偶发重试属正常。③首次运行若被杀软拦截，加白名单即可（PyInstaller 单文件常见误报）。④换翻译引擎：GUI 点"pdf2zh路径…"选择后写入同目录 `同页对照工具.config.json`，下次自动记住。

## 重新打包 exe（改了脚本之后）

```powershell
powershell -ExecutionPolicy Bypass -File build_exes.ps1
```

自动完成：临时 venv → 两个干净启动器（排除 pymupdf）+ DualEngine.exe（全量）→ 结束运行中的旧进程 → 三个 exe 拷回本目录。做完后若维护便携包，把三个新 exe 覆盖进 `同页对照工具-便携包\`。

## 参数

- `--python <解释器>`：带 `pymupdf` 的 Python（默认自动探测 venv→系统）。
- `--lang-in / --lang-out`：翻译语言对，默认 `en → zh-CN`。
- `--engine`：`siliconfree`（免费无需 key）或任意 pdf2zh_next 支持的后端名。
- `--base / --model / --apikey-env`：自定 OpenAI 兼容后端时填。
- `--p2zh <exe>`：`pdf2zh_next.exe` 路径（默认指向本机 zotero-pdf2zh）。
- `--no-rotate`：不做图纸转正（保持原方向输出；竖排正文会重新变得不可译，仅用于 A/B）。
- `--no-qa`：跳过质检快速看效果；`--deep-qa`：追加像素+覆盖率深检。
- `DUAL_NO_SUBSET=1`：禁用输出端的字体子集化。`subset_fonts` 会误删"嫁接页"里用到的字形轮廓（文字层还在、渲染空白），关掉可做到零字形丢失，代价是文件明显变大（中文字体整份嵌入，22 页样张 2.1MB → 27MB）。深检报"未解释像素差"时用它确认是否此因。
- `SYNTH_HEAL=<0|1|2|3>`：自愈级别。默认 1；引擎在每页画完后还会做**页内真值自检**（按 qa_synth 同一规则重新提取本页文本，压字单元自动挪页末并重排该页），所以常规文档第一轮即 0/0。级别 2/3=切带边距加倍 + 逐单元碰撞预测提前挪页末，作为升档兜底；0=完整旧行为（仅 A/B 调试用）。GUI/CLI 检测到告警会自动逐级升档重试，无需手动设置。
- 调试环境变量：`SYNTH_DBG=<0基页号>` 打印该页窗口/原子簇/单元/切带决策（单元带 `org`
  来源标记 `pair/attach/split/head`，另有 `ATTACH m=…` 与 `SPLIT K=… M=…` 行）；
  `DUAL_NO_SPLIT=1` 关闭条目拆条（A/B 用）。

## 工作原理（供调试参考）

0. **图纸转正**（`rot_pages.py`，在翻译之前）：逐页统计"沿基线墨长"按横/竖两个方向的占比，若竖排行数 ≥8 且竖墨长 ≥1.2×横墨长，判定为整页竖排图纸，用 `set_rotation()+remove_rotation()` **把旋转烘进内容流**（此后 pdf2zh 与引擎都当它是普通横版页）。转正副本缓存为 `translated\<名>.rotsrc.pdf`，其译文带 `.rotsrc` 标记，与普通文档的译文互不串用。**没有这一步，pdf2zh 会静默丢掉全部竖排正文**（DOC-A04 实测：96 行只译出 16 行）。
1. **对齐**：英文块与中文块按文本相似度 1:1 配对；配不上的中文（拆散的表格行、图内标注）"挂靠"到其所在英文块。
2. **窗口**：按整页水平文字行+格线+图形簇确定正文左右边界；旋转边栏/水印/出血不进入裁切。
3. **原子簇**：表格、电路图聚类为不可切分整体；切线只走簇与簇之间的空隙（`safe_cut`），页面被横向"切带"，每带下插入对应中文后整体下移。
   ⚠ 参与聚类的图元必须先按**描边宽度膨胀**（`ink_rects`）：`get_drawings` 给的单线格线是零宽/零高的矩形，`cluster_rects` 开头的 `is_empty` 会把它们整条丢掉 —— 结构竖线就不在障碍物集合里，切线直接从它们身上切过去，碎片随所在切带各移各的（机械图纸的图框/标题栏出现台阶、错位）。只膨胀本来会被丢掉的图元，有厚度的矩形原样参与。
4. **表格重建**（核心，专治"表格折成段落不可读"）：
   - 用源页**真实矢量格线**（`get_drawings` 的细横竖段）恢复行列边界：行带=横线、列带=竖线；竖走廊两侧完全独立时拆成上下堆叠的子表（VendorY p14 = 左右两半）。
   - **簇内大块炸开**：mono 译文常把整张"术语|说明"表合成一个大块——按 60% 重叠判属表后，炸成逐行单元，让每一行落进自己的真实单元格（PRODUCTLINE p4 由此重建为 2 列网格）。
   - **合并大行**：稀疏格线表里"一行装很多信息"的大行保持一个高单元格，格内按原文显示行断行（`_wrap_cell`，`\n` 为显示行分隔符），不再误拆成 N 个细行。
   - 列宽按格线物理比例分配，字号 7.6→6.0 递减试排；渲染后画蓝色网格线，首行（表头）加粗。
   - **自检回退**：任何一版排布出现行间碰撞（`_grid_collide`）或病理级超高（>2.2 页高——band 机制会把页高延展为 H+cum 容纳中文网格，故只拦真正撑爆的超大表），整表回退聚类折段，绝不输出压字的东西。
   - **表单页拆簇**（`split_form_cluster`，专治"好几张表叠在**一个连续外框**里"）：这类页的左右边框是**贯通**的，`cluster_rects` 会把它们并成一个整页大的簇，于是每一条切线都被吞掉（`cuts<=2`）——判据把它当图纸页走 overlay，而 overlay 的"就近找空白"在密集表里只能找到**别的表**的空格，译文就被塞到隔壁表去了；退回 reflow 则整页译文折成一段流水账。拆法是找"竖线在哪一行断了"：两张表的分界必然是那条横线——线上、线下的**列支撑集**是两套不同的列（`support()` 与 Jaccard < 0.5）。每片的 bbox 取**它自己那些高格线的外接矩形**，而不是分界线、也不内缩：直接按分界线切，两片严丝合缝相接，`safe_cut` 找不到落刀的空隙（切线被一路推回页底，等于没拆）；从分界线往里缩，竖线又伸进缩掉的那块，切线正好把它拦腰切断（质检①的 VCUT）。拿格线外接矩形，切线自然落进两表之间的真实表间距。此后各表各自成簇、各自重建网格，中文紧跟自己的那张表。
   - 子表矩形是**精确**的：喂给 `_grid_from_rules` 时不再外扩、收线容差也从 4pt 降到 1pt（否则隔壁表的竖线会被当成自己的列，列数 5→31、每格只剩一个字的宽，中文竖排成一条）；排版可用宽度按**整张表宽**算而不是按中文锚点范围算（中文只落在表格左半边时，后者会把网格挤成半宽、词被拆成一字一行）。
5. **标题块防污染**：封面题录栏/修订表的中文碎片只有落在水平格线围出的窗口内才挂靠插入，旋转侧栏的单字散块一律丢弃。
6. **图纸页就地叠加（overlay）**：满足任一判据即启用——① 单元多而切带少（`len(units)≥8` 且 `len(cuts)≤max(2, units//6)`，即巨型图形簇把所有切线挤到一处，切带结构已退化）；② 整页以竖排文字为主（转正被关掉或未被检出）。做法：**源页 1:1 整页绘制、一刀不切**（撕裂与像素丢失因此天然为 0），中文按"就近锚点 → 同列上下空白走廊"的顺序试排，障碍 = 每条文字行 + 每条矢量路径**按描边宽度膨胀后的矩形**（零高度的单线格线 `get_drawings` 会报 empty，必须膨胀，否则中文会压在格线上被像素审计判为 LOST），排不进的统一落到页末附录区（画一条淡蓝分隔线）。此类页的 geom 记 `"overlay":1` 且 `window=[0,W]`（整页都是安全窗口，没有窗口边缘可撕）。
   **图纸/表单落字三条规矩**（`content_frame` / `empty_form_cells`，用户要求）：
   ① **中文不许出图框**：由"长横线、长竖线"（各自长度 ≥ 55% 页宽/页高）围出的最内层包络即内容框；落字框必须整框在框内，否则这一块宁可不译 —— 也不堆到页末附录（附录同样在框外）。图框外是页边坐标带（`1..8`/`A..F`）和页脚这类图纸家具，译文落在那儿只会让人以为画错了。
   ② **不许占用空白格子**：有格线围出、里面**没有任何文字**的格子是留着填信息的（标题栏的 Ae0~Ae7、Remark、Replaces 等），整格设为障碍物。只认表格格线 —— 图纸外框线不算，否则"图框底边 + 标题栏左边"会围出一大片空白纸条被误判成格子，中文反而被赶得更远。
   ③ **没译出中文的不落字**：译文里一个汉字都没有（纯编号/日期/代号，pdf2zh 原样返回）→ 直接跳过。原文本来就在那儿，再贴一遍只是噪声。
   被主动放弃的块计入 geom 的 `skipped`（连同内容框 `frame`），并仍被质检④记成"缺项"，不静默丢失。
   ④ **落字只许在源文自己那一格内**（`source_cell`：由源文上下最近的横格线、左右最近的竖格线围出）：候选位置 = 同行右侧并排 → 本格内正下方/正上方 × 格内若干 x 位 → 本格整宽；全部必须整框落在格内、不与任何已有墨迹重叠。格内放不下就**放弃这一块**（不再丢页末附录、不再飘到几十 pt 外）——用户实测"飘到别的格/页脚"比"少贴几块"糟得多。锚点与格子都按**源文那一整块英文**算，不能按每块中文碎片自己的矩形算：碎片各不相同 → 格子各不相同 → 互相抢位、谁也放不下（实测 14 块只落得下 2 块）。
   ⑤ **空心矩形只算四条边**（`stroke_rects`：`fill is None` 的 `re` 图元，手写章框/图框）：它的 bbox 是整整一片区域，当实心障碍会把章框覆盖的格子内部全部封死，中文在格内无处可放只好挤到隔壁格或章框下面（三层文字重叠）。膨胀单线、拆空心矩形、实心图形取外接矩形 —— 这是引擎**所有**障碍物/格线的统一口径（切带、格线、质检同源）。
   ⑥ **中文纠错表 `cn_fix.json`**（与 exe 同目录，可外部维护）：机翻把工程缩写当金融词译（"New Exch. Liq." → "新交易所流动性"）时，源文那一块在 PDF 里常和整行表格粘成一个大块、按源文匹配的术语表够不着 —— 直接用"中文→中文"替换表在排版前纠正。
7. **覆盖兜底（两种模式共用）**：mono 里明明译好了、却没被任何单元带走的中文块，一律补到该页页末。最常见成因是**源段被写成一行一个文本对象**（PyMuPDF 视其为多个块），而 babeldoc 把它们合并成一个整段块——DP 对齐只能一一配对，剩下整段就被丢弃（自建 3 页正文样张实测：每页少一整段）。模板脚注（`CJKBOIL`）与页眉/页脚条（盖章、页码带）仍按设计有意不搬。**注意**：就地替换进目录点导引区的中文也算"已落地"，必须计入覆盖率，否则整块目录译文会被判成漏项、又堆到页末。
8. **目录就地替换（`toc` 级）**：目录行不切带。中文写进"标题—页码"之间的点导引区——点线只用**白色实心带按点线墨高（基线 ±3.8pt）覆盖**（源文件一字不改，不用 redaction），页码与英文标题原样保留。带会按"压着的其他正文墨迹（红章/格线）"切成多段，中文只落在空着的最宽那一段；切不出可用段或中文塞不下，该行退回"插到行下方"。这样目录页高不涨、水印/盖章不被切碎。
9. **装饰行（斜排/水印/浅灰底纹）——"摘出 → 重画"**：行高 > 2.6×字号（斜排水印的 bbox 斜跨大半页）或浅灰（RGB 三相相等且 0x40~0xC8）判定为装饰。这类行**既不当切带障碍、也不参与压字判定**——否则整页切线会被顶到页尾（几十个块折成一条带堆到页面另一头），且任何落进它那个巨大斜框里的中文都会被误报成压字。但只排除障碍还不够：切带会从它身上切过去，**每切一刀它在那带里的片段就跟着平移**，页面上出现一叠错位碎片（"水印被截断"）。所以还要（见 `decor.py`）：
   - `collect()` 用 `get_texttrace` 取它的文本/字号/颜色/透明度/方向/逐字原点，并抽取内嵌（子集）字体；
   - `clean_page()` 做一份单页副本，把该文本块整个置空（`BT ET`），再用**文本抽取自校验**：装饰文字消失、其余文字一字不差，否则返回 None 退回原页（宁可有碎片，绝不误删正文）；
   - 切带用这份"清洁页"来拼，切完整条**按原位置重画**（`TextWriter` + `morph` 旋转 + `opacity`）。注意 PyMuPDF 的 `Matrix(deg)` 与 `get_texttrace` 的屏幕方向符号相反：`dir=(0.707,-0.707)` 对应 `Matrix(45)`。
   - 像素审计的参考页必须走同一条路（也拿清洁页拼带 + 同一份规格重画）；若改成"抹白原页碎片"，会连碎片底下的正文一起抹掉，反而把正常内容报成丢失。
   - 重画必须排在**目录就地白带之后**：白带只该盖点导引，否则会把水印擦掉一道。
10. **排版可读性度量**：每个译文块记录"实际落点距它所属原文/原子簇底边的距离"，随 geom 侧车落盘（`far`/`maxjump`/`nunits`），供质检⑤判定；正常相邻插入 ≈ 0~2pt。

## 常见问题与结论（踩坑记录）

| 症状 | 根因 | 处置 |
|---|---|---|
| 表格中文挤成一坨长段落 | 早期只有关键词折叠 | 已建格线网格引擎（见上） |
| 中文表把一行拆成十几行 | 对稀疏格线表误按文字行细分 | 行边界只认**真实横线**；格内多行合并 |
| VendorY 表格右侧被竖条啃掉 | 窗口左边界不许向左长 | `bx0` 允许 ≤10pt 微扩并吸纳格线 |
| 封面题录表冒出孤立中文词 | mono 把表格文字打散成碎片 | 格线窗口判定 + `CJKBOIL`/`BOILER_RE` 模板过滤 |
| 长单词（`AAA24831AC5`）撑爆窄格 | wrap 只会按空格断 | `cell_wrap` 硬切超长 token |
| 像素审计报"丢失" | 用了旧 `.geom.json`（与输出不配对） | 引擎改动后必须重跑 `make_dual`（侧车随输出一起再生） |
| 保存报 `FzErrorSystem ... Permission denied` | 输出 PDF 正被查看器占用 | 入口已预检并提示关查看器；应急：先 `-o` 输出到临时路径再复制 |
| PowerShell 里脚本崩溃 `UnicodeEncodeError: gbk` | 控制台默认编码 | 先 `$env:PYTHONIOENCODING="utf-8"` |
| 深检仍有"中文缺项块" | 页脚/版权/保密条款等模板内容**有意不译** | 属设计选择，正文页出现才需核查 |
| 译文格内出现重复词（"导线 导线"） | pdf2zh 翻译阶段留痕，本工具只搬运不改写 | 要修请改译文 mono 或术语表 |
| 双击 exe 在线翻译报"翻译未产出（pdf2zh 退出码 0）"，调试日志见 `onnxruntime … 初始化例程失败`（babeldoc 会误报"请安装 VC++"） | **PyInstaller 单文件启动器的包里只要含 PyMuPDF 的二进制（哪怕运行时从不 import），它 spawn 的 pdf2zh→babeldoc 孙进程 onnxruntime 必挂**。经 A/B 探针定位：同代码同环境的 exe，不含 pymupdf → 翻译成功，含 pymupdf → 100% 失败；环境变量逐字节一致，清 env 无效，cmd 包装也无效 | **双 exe 架构**：`同页对照工具.exe / DualGuiCLI.exe` 构建时 `--exclude-module pymupdf` 且构建目录不放引擎 py（保持"干净"，专职发起 pdf2zh）；合成/QA 交给同目录 `DualEngine.exe`（含 pymupdf、不开子进程）。翻译失败自动重试 3 次 |
| 源页红字被我方 dump 当成"蓝插文" | 判色按 `color != 0` | 真插文是纯蓝 `(0,0,1)`；红/灰都是源内容 |
| 中文行"碰撞"某几个单字母碎行（`f`/`O`/`CO`） | `safe_cut` 判定有 0.5pt 逃逸窗：推进 `y1+1.4` 恰好落进下一行墨框顶部，行首被切出一丝残片——文字层却报告完整 bbox，与中文带重叠 | 保护带 `[y0-0.15, y1+0.25]`、推进改 `y1+0.5`（逃逸窗关闭且严格单调收敛）；另有自愈级别 2/3 兜底：预测仍压字的块自动挪到页末 |
| 竖版图纸（PCB/机械图）译文只剩零星几行 **且** 成品左右被切穿 | pdf2zh/BabelDOC **不处理旋转文字**（DOC-A04：96 行只出 16 行），而切带窗口只按横排行算宽度，必把竖排内容拦腰切断 | 翻译前 `rot_pages.py` 物理转正（工作原理 0）；竖排主导页一律走 overlay 不切带（工作原理 6） |
| overlay 中文压在细格线上，像素审计报 LOST | 单线格线在 `get_drawings` 里是零高度矩形，被 `is_empty` 过滤掉 → 等于没有障碍物 | 每条路径矩形按**描边宽度**膨胀后再当障碍 |
| `DualEngine.exe --rotate` 崩 `no such file: '--rotate'` | 委托调用没把标志从 argv 剥掉，`rot_pages` 把 `--rotate` 当成了输入文件名 | `main()` 里先 `sys.argv = ["dual_gui"] + args[1:]` 再调用 |
| 图纸里的孔数表/符号表整块没译 | 那些"文字"是**矢量轮廓**，PDF 文本层里不存在（无文本、无图片、无 XObject） | 任何基于文本的翻译都无能为力，只能 OCR；本工具不假装翻译，源内容保持 1:1 |
| 正文整段中文不见了，可撕裂/碰撞/像素差却全是 0 | 源段被写成"一行一个文本对象"（每行单独成块），mono 把它们合并成一个整段块；DP 对齐一一配对，剩下那段无处挂靠就被静默丢弃 | 覆盖兜底：凡未被任何单元带走的 mono 中文块一律补到该页页末（工作原理 7） |
| 合成跑到一半崩 `FzErrorFormat: kid not found in parent's kids array`（GUI/CLI 都可能在"页内真值自检"要重建该页时触发） | 重建页用的是"先 `delete_page` 再 `new_page`"，而被删的那页既是 `new_page` 建的、又经过 `show_pdf_page` 嫁接、**且是文档里唯一一页**——MuPDF 直接抛错 | 重建改成**先落新页、再删上一轮那页**（`nd.delete_page(len(nd) - 2)`）：新建页已存在 → 被删页不再是唯一页 → 安全。删页后还要按索引重新取回本页活对象（见下表 `is_pdf` 那行） |
| 密集表格页/正文页整页译文被堆到页末，撕裂/碰撞/像素全 0，成品根本没法读 | overlay 判据 `len(units)>=8 and len(cuts)<=max(2, units//6)` 几乎恒为真 —— 一张普通表格的几十个格单元本来就折进同一条带，units 一大、cuts 就显得"少"，于是所有密集页都被误判成图纸页，而 overlay 在密集页上找不到空白，只能把整页译文堆到页末 | 判据改为"切带结构真的塌陷"（`len(cuts)<=2`，即全页被一个巨型图形簇占据、压根没有可用横带）；再加**结果导向安全阀**：overlay 试排后若丢页末比例 >22% 自动退回切带重排 |
| 第 1 页目录整页译文变成页末一坨流水账，可读性差、排版差 | ① babeldoc 把整页目录切成"开头两行各一块 + 其余 96 行一整块"，大块配不上对只能挂靠，而挂靠单元 `mi=None`、旧代码直接跳过逐行展开；② 就地写入的中文没计入"已覆盖"，被判成漏项又补到页末 | 目录改为**就地替换点导引区**：译文取用与 mono 怎么切块无关（按源行编号序列切段）；中文写进"标题—页码"之间，页高不涨；`have` 计入就地译文 |
| 目录行末尾几个字母被抹掉；红章"DOC 受控"被整块删掉（不可逆） | `find_dot_span` 按"字符数比例"内插估算点线起点，标题字宽远大于句点宽度时偏差可达 20pt，抹白时切进标题；且旧实现用 `apply_redactions` 删文字，会把同一行的红章一起删 | 点线起点改用 Helvetica 真实字宽度量（与 Arial 度量一致）；不再用 redaction，改为**只覆盖点线墨高（基线 ±3.8pt）的白色实心带**，并把带按"压着的其他正文墨迹"**切成多段**，中文只落在空着的那一段里 |
| 两张相邻规格表的中文一起变成流水账段落 | 同一条切线把两张表的单元合并为一组，并集 `env` 既不属于表1也不属于表2，`inside` 判定失败 → 整组退化成段落（p3/p4 两张规格表就是这样垮的） | `_fold_group` 先**按所在图形簇拆组**，每张表各自走 `_grid_from_rules` 重建网格 |

## 改引擎后的验收流程

```powershell
$env:PYTHONIOENCODING="utf-8"
& $py make_dual.py <src.pdf> --mono <mono.pdf> -o <out.pdf> --deep-qa   # 每份都要 0/0/0/0
```

四项都要归零：`撕裂=0 碰撞=0 排版告警=0`，深检再加 `未解释像素差页=0`。
`qa_layout.py` 现在打印 `page units far appendix parked_cn maxjump order` 六列，**五类**告警
（落点过远 / 页末堆积 / 过小字号 / 编号错位 / 译文顺序颠倒）任一非零即退出码 1、
`make_dual` 不再标"可交付"。

回归基线样张（某电梯厂商 ×2、VendorY、PRODUCTLINE 变压器、PRODUCTLINE 竖版 PCB 图纸 DOC-A04、表单页 DOC-A07）：表格页网格行列数应与源格线一致，正文页不得新增碰撞/撕裂，像素差恒为 0；图纸样张还要 `转正=1 页` 且 overlay 生效（`levels` 里出现 `overlay`）。目录页则要求 `levels` 里不出现 `toc`（全部就地替换），且合成器那行"排版距离"里"落点过远"应在 1% 以内。表单页反过来要求**不出现** `overlay`（`cuts` ≥3、各子表各自出网格）、页末丢弃 `parked=0`、落点过远 0。

批量回归用 `_diag/regress_all.sh <引擎目录> <输出子目录名>`（工作区 20 份样张一份汇总表：
TEAR/COLL/LAYOUT/PXDIFF/FAR/ORDER + nummis）。**默认并行 `JOBS=8`**，全量约 1m20s；
`QUICK=1` 跳过两项像素审计（并行后只省 6s，意义不大）；迭代期可用 `ONLY`/换小样张集。
成品重出用 `_diag/deploy_all.sh`（同样 `JOBS=8`，20 份含 `--deep-qa` 约 2m24s；
`ONLY=` 抽查、`OUTSUF=.t` 试跑不覆盖交付件）。

**A/B 开关（做归因时用）**：`DUAL_NO_HOSTMERGE=1` 关掉"同一宿主合并"（回到 pair/attach
各自落位的旧口径）、`DUAL_OLD_SPLIT=1` 回改动前的拆条口径、`DUAL_NO_SPLIT=1` 全关拆条、
`DUAL_NO_PATHFIX=1` 只关"多行单元落点下移"。**注意 `_diag/engine_old/` 目录已不再是
'改动前引擎'**（会被临时探针覆盖），归因一律用开关，别再依赖那个目录。

### 为什么"改一行代码"会花掉几分钟（2026-09-28 实测，别再重复踩）

| 阶段 | 单页样张 | 9~10 页大文档 |
|---|---|---|
| `python -c "import pymupdf"`（**每个进程的固定开销**） | 1.2s | 1.2s |
| synth | 2.4s | 17~21s |
| qa_tears / qa_synth / qa_layout | 1.2 / 1.3 / 1.2s | 1.4 / 3.2 / 2.4s |
| audit_build / audit_px | 1.4 / 1.5s | 2.4 / 5.7~6.8s |

单页样张跑完 6 个阶段要 9s，其中 **7.2s（80%）是 6 次进程启动/import**。所以：
① **先并行**（样张之间完全独立，24 核空着是纯浪费）——6m→1m20s；
② 再想省时间就动**最慢的那一份**（Z_45335259 自愈升到第 4 级要 113s，是全表的关键路径）；
③ 别指望 `QUICK`（跳过像素审计）能省多少，并行后它只占关键路径 6s。
